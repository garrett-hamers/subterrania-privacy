Privacy Policy for SubTerrania

Last updated: October 9, 2026

Overview

SubTerrania is a single-player turn-based strategy game developed by Atlyn (Garrett Hamers). All gameplay runs on your device and the game is playable without a network connection. When diagnostic reporting is configured in the build and the corresponding in-app switch is on, the app sends diagnostic and gameplay-outcome telemetry to Microsoft Azure Application Insights to help us detect crashes and balance the game. As of version 1.3.0, you can turn crash reports and usage analytics off independently inside the app. This policy applies to the Android game, not to Atlyn website accounts or Power BI products.

The game has no player accounts, advertising SDKs, or in-app purchases. The information described below is used for diagnostics and analytics, not advertising.

What We Collect

Diagnostic telemetry (Azure Application Insights)

When diagnostic reporting is configured, your device has an internet connection, and the matching switch is on, SubTerrania sends the following events to Azure Monitor (operated by Microsoft):

  • app_start — every time the app launches
  • game_started — with the chosen difficulty, character, and map
  • game_won / game_lost — with difficulty, character, map, turn number, and victory points earned
  • active_game_persistence_failed — when saving or loading your resumable game fails, with which operation failed (save, load, or clear) and nothing else
  • game_completion_persistence_failed — when recording a finished game fails, with the failure-stage enum name
  • game_completion_exit_refused — when leaving a finished game is refused because its result is not recorded, with the fixed reason completion_unrecorded
  • meta_progression_persistence_failed — when saving a non-completion progression/settings change fails, with the fixed operation settings
  • feedback_sent — when you tap the feedback option in the in-app settings. This records only that you opened your mail app; the message you write is composed and sent by your own mail app and never reaches us through telemetry.
  • Uncaught exceptions (crashes) including the stack trace, exception type, and message — but no game contents

Each event also includes the app version, Android API level, and device model name. A randomly-generated instance ID is regenerated for every envelope rather than persisted as a player, device, or installation identifier. Crash reports also include the exception message and stack trace supplied by the crashing code.

Approximate network location

Microsoft Azure necessarily receives a connection IP address when processing an HTTPS request. Azure derives approximate geographic information, such as a network region, from that address and retains it with the diagnostic records. Raw client IP addresses are masked in our telemetry records. Masking the stored IP does not prevent this geographic derivation. The game does not request Android location permissions, GPS coordinates, or precise device location.

What the game does not request or send

  • Your name, email, account identifier, or any contact information
  • Your game-save contents, board layouts, or any free-form text you might type
  • Any persistent device or installation identifier (no advertising ID, no Android ID, no install UUID)
  • Your contacts, GPS coordinates or precise location, camera, microphone, files, or browsing history

Permissions

The game uses these permissions for its own functionality:

  • VIBRATE — for haptic feedback during gameplay. No data collection.
  • INTERNET — used solely to send the telemetry described above to Azure Application Insights. The app never accepts inbound connections, and gameplay continues to work if the network is unavailable (telemetry is silently dropped).

Third-Party Services

SubTerrania uses one third-party service:

  • Microsoft Azure Application Insights — receives the diagnostic telemetry described above as our data processor. See Microsoft's privacy statement for how Microsoft handles data sent to its services.

The app does not integrate with any analytics SDK, advertising network, social-media SDK, or third-party login provider.

Data Retention

Our diagnostic event and exception tables have a 90-day retention period; records expire under that retention policy. The telemetry has no persistent player, device, or installation identifier for locating one person's records on request. Turning the switches off stops future collection but does not delete records already transmitted. Contact us for a privacy inquiry or to discuss these practices.

Opting Out

Open Settings inside the app and find the Privacy section. It contains two independent switches:

  • Crash reports — the crash stack traces described above.
  • Usage analytics — the named gameplay events described above.

Both are on by default and either can be turned off at any time. Turning one off takes effect immediately: those sends stop, and anything already queued on your device but not yet transmitted is discarded rather than sent later. With both switches off, the telemetry system does not start at all — no background worker and no crash handler are installed.

Earlier versions of this page suggested disabling the app's network access in Android settings. That advice was wrong: Android does not offer a way to withdraw the ordinary INTERNET permission from an installed app. The in-app switches are the real control, and they are the only one you need.

Children's Privacy

SubTerrania is not directed at children under 13. It has no player accounts and does not request names, contacts, advertising identifiers, or precise device location. The diagnostic and processor-derived information described in this policy is still collected when reporting is enabled.
